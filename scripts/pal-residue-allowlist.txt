# WoofWare.PosixKernel definitions that speak WoofWare.PawPrint's CoreCLR PAL
# rather than POSIX. Checked by scripts/check-pal-residue.py, which runs as the
# `pal-residue` flake check.
#
# There are none. This file is deliberately kept, empty, because its job has
# changed rather than ended: it used to record how much of the extraction was
# still owed, and it now records that the answer is none, so that adding an
# entry is a visible act somebody has to argue for in review.
#
# The four clusters, and where each went (docs/plans/2026-08-23-posix-kernel-
# extraction.md has the reasoning):
#
#   errno numbering        -> WoofWare.PawPrint's `UnixErrorPal`        (stage 7)
#   `SocketEvents` bits    -> `SocketEventsPal`                         (stage 9g)
#   `AF_*`/`SOCK_*`/`PT_*` -> `SocketArgumentsPal`                      (stage 9h)
#   `PosixSignal` enum     -> `PosixSignalPal`                          (stage 9i)
#
# The library states the raw `<errno.h>` number, epoll's own readiness
# conditions, the set of sockets it will create, and a signo; each client
# encodes those as it pleases.
#
# A new conversion between POSIX and a .NET encoding belongs in
# WoofWare.PawPrint, beside those four, with the POSIX value handed to the
# library. If you believe an exception is warranted, add it below with a comment
# saying why, and expect to be asked.
